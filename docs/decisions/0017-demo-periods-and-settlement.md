# 시연용 기한 단축과 즉시 정산 실행

- 상태: 제안·구현 전
- 제안일: 2026-11-14
- 연결 이슈: [#386](https://github.com/500-internal-server-error-team/commerce-settle/issues/386)
- 범위: 같은 시험 거래를 주문·환불·구매확정·정산·모의 지급까지 짧게 시연하기 위한 실행 방식

## 문제와 선택

현재는 발송 후 2~3영업일의 모의 배송과 배송완료 후 168시간의 환불 요청 기간을 거쳐야 자동 구매확정됩니다. Settlement에 결제 원장과 구매확정이 모두 준비된 항목은 그 이후 첫 10시 일배치에서 지급을 준비합니다. 배치 실행 버튼만 추가해도 구매확정 전 거래는 정산할 수 없습니다. 현재 정책은 [업무 정책](../policies.md#배송환불-기한과-자동-구매확정), 제공 중인 시연 기능은 [개발 환경](../development.md#데모실험-ui)을 따릅니다.

**전용 시연 환경에서 새 주문의 배송·환불 대기를 단축하고, 준비된 거래를 현재 시각 마감으로 고정해 실제 Spring Batch 실행 경로로 처리하는 안을 제안합니다.** EC2·앱·DB의 시각과 인증·작업 임대·재시도 시간은 유지합니다. 이 문서는 설계 제안이며 설정·API·DB·배포를 변경하지 않습니다.

| 검토한 안 | 판단 |
| --- | --- |
| EC2 또는 전역 Clock 이동 | 채택하지 않음. 세션·임대·재시도까지 영향을 받으며 SQL의 실제 시각과 어긋날 수 있음 |
| 배치만 수동 실행 | 이미 준비된 거래에는 유효하지만 배송·환불·구매확정 대기를 해결하지 못함 |
| 구매확정·환불 검사를 생략 | 채택하지 않음. 실제 상태 전이·환불 배제·금액 보존을 시연할 수 없음 |
| 주문별 기한 단축과 회차별 즉시 정산 | 제안. 실제 시각과 기존 처리·예약·지급 로직을 유지하면서 시연 대기를 줄임 |

## 시연 모드와 주문 기한

- 기본값은 비활성입니다. 시연 모드는 DB·Kafka 토픽/그룹·Redis가 다른 업무와 분리된 모의 금융 환경에서만 켭니다. 같은 EC2를 쓸 수 있지만 공용 서비스의 전역 설정을 바꾸지 않습니다.
- 전용 환경에서는 정기 일배치와 판매자 대역 자동 발송을 끄고, 시연 단계에서 명시적으로 실행합니다. 모드와 실행 설정이 맞지 않으면 기동을 거절하도록 검증합니다.
- 시연 모드에서 **새로 생성한 주문**에 별도 정책 버전과 배송 대기·환불 요청 기간을 고정합니다. 초기 제안값은 배송 5초·환불 10초이며 리허설 전에 정합니다. 기존 주문은 설정 변경·재시작으로 재해석하지 않습니다.
- 발송 시각에 배송 예정 시각을, 배송 예정 시각에 환불 마감을 계산합니다. `현재 시각 > 환불 마감`이고 진행 중인 취소·반품·환불이 없어야 구매확정합니다. 설정을 꺼도 저장한 기한과 거래 이력을 되돌리지 않습니다.
- 일반 모드의 배송·환불 정책은 유지합니다. 단축 시연은 일반 정책의 2~3영업일·168시간 경계를 검증한 결과로 표시하지 않습니다.

## 실행 단계와 책임

| 단계 | 실행 조건과 결과 | 소유 |
| --- | --- | --- |
| 회차 고정 | 매진과 시연할 환불의 완료를 확인하고 대상 주문·판매자 집합과 정책을 고정 | Commerce의 소유 조회·검증, demo-control의 호출 조율 |
| 발송 시작 | 남은 유효 결제 주문을 기존 발송 경로로 처리. 이때 짧은 배송 대기가 시작 | Commerce |
| 기한 처리 | 실제 기한이 도래한 배송·구매확정만 기존 전이·Outbox 경로로 처리. 미도래·진행 중 환불은 건수와 이유 반환 | Commerce |
| 정산 준비 확인 | 회차의 결제 원장·구매확정 수신과 환불 완료를 확인. 전송 대기와 업무 실패를 구분 | Settlement |
| 정산 실행 | 대상·마감을 고정하고 실제 Spring Batch Job의 판매자별 처리·지급 작업 생성 경로 실행 | Settlement |
| 지급 결과 | 기존 지급 워커·모의 금융·알림을 거쳐 같은 회차의 금액과 상태 조회 | Settlement·기존 지급 워커 |

demo-control은 로컬 UI와 기존 운영 자격으로 소유 서비스에 요청을 전달합니다. 다른 서비스 DB를 직접 고치거나 금융 원장을 대신 만들지 않습니다. 운영 명령은 기존 내부 인증·멱등키·감사를 사용하며 Gateway의 공개 구매자·판매자 API로 노출하지 않습니다.

기한 처리 버튼은 정기 스케줄러를 기다리지 않고 같은 업무 처리를 깨우는 용도입니다. 아직 도래하지 않은 시각을 넘긴 것으로 간주하지 않으며, 요청 단위 처리 상한·페이지 진행과 미완료 이유를 반환합니다. 자동 발송이 부하 시험 중 먼저 시작돼 환불 기한이 끝나지 않도록, 매진·시연 환불 완료 뒤 발송 단계를 시작합니다.

## 즉시 정산의 마감·회차·재시작

1. 시연 회차는 일별 `batchDate`와 별도의 `runId`로 식별합니다. 서버가 고정한 주문·판매자 집합을 reader와 판매자 항목 선점 **양쪽**에서 검사합니다. 전액 환불 완료 주문은 제외 근거로 보존하고 나머지 미예약·미지급 항목에 준비 조건을 적용합니다. 브라우저의 선택값만으로 지급 범위를 인정하지 않습니다.
2. 원장·구매확정·환불 반영을 확인한 뒤 서버의 실제 현재 시각을 `cutoffAt`으로 고정합니다. 모든 대상의 `readyAt < cutoffAt`을 검사합니다. 같은 마이크로초에 준비된 항목 등 마감 전 조건을 충족하지 못하면 마감 저장·실행 전에 대기로 돌려주며, 미래 시각을 만들거나 `<=`로 바꾸지 않습니다.
3. `runId`, 대상, 정책과 마감은 한 번 저장한 뒤 바꾸지 않습니다. 같은 키·본문은 같은 실행과 결과로 연결하고 다른 본문은 충돌로 거절합니다. 새로운 시연은 새 회차로 시작합니다.
4. Spring Batch의 reader·writer와 판매자 정산 처리가 같은 대상·마감을 사용하도록 확장합니다. 기존 운영자 정산 생성 API 호출을 일배치 Job 실행으로 표시하지 않습니다. 일배치 완료와 지급 성공은 각각 확인합니다.
5. 실패·정상 중단은 고정한 회차로 재시작하고, 실행 중 재요청은 중복 실행을 만들지 않습니다. 강제 종료 잔류는 기존 실행자 부재·정체 확인을 거칩니다. 완료된 회차에 늦은 이벤트를 추가하지 않으며 새 회차에서도 이미 예약·지급한 항목을 다시 배정하지 않습니다.
6. 일반 10시 일배치와 시연 실행이 같은 항목을 가져가지 않게 합니다. 전용 환경의 정기 실행 비활성을 기동 시 검증하고, 시연 거래와 회차의 선택 범위를 업무 처리에서도 검사합니다. 미완료 회차가 있는 환경을 모드만 끄고 일반 업무로 재사용하지 않습니다.

현재 배치·reader·판매자 선점은 `batchDate`의 10시 마감을 사용하며 배치 키도 판매자·날짜·정책 버전 기준입니다. 따라서 시연 회차·기간 스냅샷·마감 저장과 회차별 유니크 제약이 추가로 필요합니다. 정책 버전에 임의 회차 값을 붙여 날짜별 중복 검사를 피하지 않습니다. API 경로·필드와 스키마는 위 불변식을 기준으로 후속 구현 PR에서 합의하고 [DB 적용 정책](../migrations.md)을 따릅니다. 기존 지원을 주장하는 계약·DDL은 이번에 바꾸지 않습니다.

## UI와 촬영

기존 비활성 `다음 업무 시각으로 이동` 버튼은 기능 구현 시 실제 동작에 맞게 `시연 단계 실행`으로 바꾸는 안을 권장합니다. 기능 활성·대상 회차·대기 이유를 소유 서비스 응답으로 확인하고, 배송·환불 기간과 정산 마감을 화면에 표시합니다. 단순히 프런트 버튼만 활성화하지 않습니다.

화면은 **정산 준비 → 실제 배치 실행 완료 → 모의 지급 성공**으로 연결합니다. 자막은 `시연 모드: 배송·환불 대기 단축`과 실제 설정값·회차 마감을 표시합니다. 일반 정책의 시간이 흘렀다거나 10시 정기 실행이었다고 표현하지 않습니다. 현재 일배치는 같은 판매자의 일반 상품도 합산하지만, 제안한 시연 배치는 고정한 회차에 명시적으로 포함된 지급 대상만 합산합니다. 두 경로의 대상·합계를 섞지 않습니다.

## 구현 완료에 필요한 검증

- 기본 비활성·일반 주문 정책 보존, 시연 전용 환경·정기 실행 설정의 기동 검증
- 신규 시연 주문의 정책·기간 고정, 기존 주문·재시작·설정 변경의 기한 불변
- 부하·매진·환불 완료 뒤 발송 시작, 미도래 처리 거절과 기한 경계, 환불/구매확정 경쟁
- 회차 밖 주문·판매자·일반 항목의 조회 및 선점 거절, 원장·구매확정 전달 대기, 진행 중 환불의 실행 차단
- 실제 현재 시각 마감과 `readyAt < cutoffAt`, 같은 마이크로초·늦은 이벤트·무대상 회차 처리
- 실제 Spring Batch 실행, 회차별 중복·본문 충돌·실패/강제 종료 재시작, 같은 날 다음 회차의 중복 배정·지급 방지
- 실제 시각의 인증·SQL 임대·재시도 보존, 표준 모의 지급 왕복·원장/정산/지급 금액 대조
- 새 전용 환경에서 문서화한 준비·실행·재실행·종료를 검증하고 UI·배포본 활성 상태와 회차 결과 확인

이번 PR의 검증은 기존 코드와 설계의 대조·문서 검토까지입니다. 위 실행 검증과 기능 제공은 후속 구현의 완료 조건입니다.
