# 본인 카카오톡으로 거래 알림 시연

- 결정일: 2026-11-02
- 상태: 시연 범위 채택. 구현·검증 범위는 [개발 환경](../development.md#본인-카카오톡-시연)에서 관리

## 결정과 이유

지정한 시험 구매자·판매자의 거래 알림을 시연자 본인 카카오 계정의 **나와의 채팅**으로 보냅니다. 기본 채널은 `MOCK_KAKAO`이며 실제 전송은 명시적으로 켠 시연 설정에서만 사용합니다. 내부 수신자의 종류·ID·소유권은 유지하고, 본문에 구매자·판매자를 구분합니다.

11월 4일 백엔드 MVP 시연은 주문·결제·발송 API가 만든 알림이 카카오톡에 도착하는 과정을 보여주는 것이 목적입니다. 모의 발송만으로는 이 경계를 확인할 수 없어 공식 self-send REST API를 선택합니다. Commerce의 기존 알림 저장·집계·발송 Worker를 확장하고 금융 처리나 별도 알림 프레임워크를 만들지 않습니다.

## 비교한 대안

- 모의 발송 유지: 기본 개발·자동 검증에는 계속 사용하지만 실제 카카오 수신 시연을 충족하지 못합니다.
- 상용 알림톡: 여러 실제 고객에게 발송하려면 비즈니스 채널·수신처·승인 템플릿 등 별도 계약이 필요합니다. 이번 본인 수신 시연 범위를 넘습니다.
- 친구 발송·여러 카카오 계정 연결: 별도 사용자 연결과 권한이 필요하며 이번 시연의 수신자는 한 명이므로 도입하지 않습니다.

## 한계와 운영 비용

self-send에는 모의 수신부의 deliveryId별 멱등·원수신 조회 계약이 없습니다. 응답 유실·시간 초과·해석 불가 응답에서는 발송 여부를 확정하지 않습니다. 해당 건은 자동 재발송 대신 수동 확인 대상으로 보존하며, 운영자가 재발송하면 중복 메시지가 생길 수 있습니다. 확정 거절과 재시도 가능한 정형 거절은 구분합니다. 정형 일시 거절의 유한 자동 재시도에도 제공자 멱등 보장이 추가되는 것은 아니므로 정확히 한 번 발송을 보장하지 않습니다. 카카오 API의 성공 응답도 읽음이나 단말 팝업을 증명하지 않습니다.

사용자의 앱 설정·본인 로그인·`talk_message` 동의와 토큰 갱신·재인증이 필요합니다. 자격은 Git 밖의 비밀 파일로 공급하며 한 시연 인스턴스만 실행합니다. 실제 금융 notice 생산부·주문 반영·발송을 연결하지 않은 시험이나 HTTP 대역 검증을 전체 시연 성공으로 표시하지 않습니다. 상세 발송·권한·복구 기준은 [거래 알림 정책](../policies.md#거래-알림)이 소유합니다.
