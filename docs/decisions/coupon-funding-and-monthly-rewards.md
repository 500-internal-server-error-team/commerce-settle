# 쿠폰 비용 부담과 월간 우수고객 선정

상태: 팀 기획을 반영한 제안. API·DB 담당자와 PR에서 확정합니다.

## 배경

신규 고객 확보, 플랫폼 재구매, 판매자 고객 모집을 각각 지원합니다. 비용 부담자와 발급 대상을 구분하며, 이 결정은 발급 권한·배치·할인 비용 기록·유일성 제약에 영향을 줍니다.

## 결정과 이유

- **세 종류를 유지합니다.** 웰컴·월간 우수고객은 플랫폼 부담, 판매자 쿠폰은 해당 판매자 부담입니다. 공통 발급·예약·환불 구조를 쓰고 처리 시스템을 나누지 않습니다.
- **플랫폼 쿠폰은 정해진 기준으로 자동 발급합니다.** 가입 여부와 전월 확정 구매 실적에 따라 대상·금액이 결정되므로 개별 승인 없이 같은 기준을 적용합니다. 운영자용 캠페인 관리·승인·수동 조정 기능은 초기 프로젝트 범위에서 제외합니다.
- **월간 쿠폰은 플랫폼 전체 상위 100위와 동점자에게 지급합니다.** 전월 구매확정 거래의 외부 결제액 합계로 정하고 취소·환불은 제외합니다. 구매 횟수를 다시 곱하지 않습니다. 등급은 선정된 고객의 할인액만 정하며, 양의 구매 실적이 있는 선정자에게 최저 혜택을 적용합니다.
- **동점자를 계정 ID로 제외하지 않습니다.** 같은 구매 실적에 같은 자격을 줍니다. 배치가 대상·등급을 고정하고 실제 인원과 할인 총액을 계산해 발급합니다. 예를 들어 브론즈 104명이 선정되면 예정 할인액은 312,000원입니다. 플랫폼 쿠폰에 사전 수량·예산 상한이나 승인·재승인을 두지 않습니다.
- **판매자 쿠폰은 자유 캠페인으로 발급합니다.** 판매자별 상위 100명 자동 발급은 신규 고객 모집을 제한하므로 적용하지 않습니다. 판매자가 대상·기간·수량·예산을 정하며, 같은 구매자도 서로 다른 캠페인의 쿠폰을 받을 수 있습니다.
- **주문에는 쿠폰 한 장 또는 마일리지를 적용합니다.** 쿠폰 간·쿠폰과 마일리지의 동시 사용을 막아 할인 비용과 환불 금액을 명확히 합니다.
- **구매자 결제액과 판매자 정산액을 구분합니다.** 플랫폼 지원액은 플랫폼이 보전하고, 판매자 할인은 수수료 기준 상품대금에서 뺍니다. 최초 금액을 보존해 환불 시 상쇄합니다.

## 영향과 한계

월 배치는 플랫폼 쿠폰만 처리하며 미완료 회차를 같은 대상·업무 키로 자동 재개합니다. 구매자·월별 발급 유일성은 월간 쿠폰에 적용하고, 판매자 쿠폰은 템플릿·구매자별로 중복을 막습니다. 판매자가 정한 수량·예산은 해당 캠페인의 비용 통제로 유지합니다.

등급 조건 충족자 전원 지급안은 채택하지 않고 상위 100위와 동점자에게 지급합니다. 플랫폼 쿠폰의 사전 예산 상한 미설정은 자동화와 별개로, 지급 조건을 충족한 고객 모두에게 혜택을 준다는 정책 선택입니다. 동점자로 인해 월 할인 총액은 달라지며, 자동 계산이 실제 지급 현금을 만드는 것은 아닙니다. 판매자 지급 전 자금 확인은 유지합니다. 100명·등급 구간이 사업적으로 최적이라는 실증 결과는 없으며 실제 효과는 추가 재구매와 비용 차감 후 이익으로 확인해야 합니다.

쿠폰·마일리지의 도메인 구분과 배포 경계는 [도메인 책임 분리 결정](0004-domain-responsibilities.md)을 따릅니다. 금액·기한·손익 가정·비용 기록·환불의 기준은 [업무 정책](../policies.md#쿠폰), 구현 계약은 [API](../api.md#쿠폰-사용-순서)와 [데이터 모델](../data-model.md#쿠폰)에 둡니다. 이 기록은 실제 발급이나 수익 검증을 뜻하지 않습니다.
