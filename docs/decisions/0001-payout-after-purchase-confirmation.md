# 구매확정 후 첫 일배치 자동지급

- 상태: 채택·구현 예정
- 채택일: 2026-10-27
- 범위: 모의 배송·환불 기한·판매자별 일일 지급·플랫폼 모의 선지급과 PG 회수

## 결정

**모의 배송완료 → 7일 환불 요청 기간 → 자동 구매확정 → 첫 일배치 자동지급**을 구현 기준으로 채택합니다. 상품 등록일부터 14일마다 지급하던 설계를 대체합니다. 구체적인 시각·달력·예약·재원·복구는 [업무 정책](../policies.md#배송환불-기한과-자동-구매확정), 요청/이벤트는 [API](../api.md), 저장 구조는 [데이터 모델](../data-model.md)이 소유합니다. 업무 흐름·테이블 구현은 아직 완료하지 않았습니다.

## 선택 이유와 대안

판매자가 받을 금액과 시점을 예측하고 지급 준비 후 추가 대기를 줄이는 것이 목적입니다. 결제일부터 환불 기한을 세면 늦게 발송한 주문이 수령 전에 마감될 수 있으므로 모의 배송완료를 기준으로 바꿉니다. 환불 진행 거래의 재원을 보호하고 지급/환불의 중복 선점을 막는 조건은 유지합니다.

| 검토한 안 | 판단 |
| --- | --- |
| 상품 등록 기준 14일 회차 | 상품마다 지급 일정이 다르고 준비된 거래도 다음 회차까지 기다리므로 대체 |
| 월 2회 마감·25일/익월 10일 지급 | 합산·송금 건수 축소에 유리하나 지급 준비 후 대기가 남아 보류 |
| 결제일+14일 지급 | 일정은 단순하지만 일찍 준비된 거래도 기다리므로 보류 |
| 구매확정 후 첫 일배치 | 추가 대기를 줄이고 판매자별 합산이 가능해 채택 |

공휴일 없이 월요일 10시에 발송하고 2영업일 배송이면 수요일 10시 도착, 다음 수요일 10시 환불 마감입니다. 마감 정각 요청은 허용하므로 자동 확정은 그 이후이며, 선행 원장까지 준비된 뒤 첫 마감에서 지급합니다. 선지급 재원은 항상 충분하다고 가정합니다. 정산·모의 지급은 주말·공휴일에도 매일 처리합니다. 배송 지연·진행 중 환불·지급 결과 미확정이면 늦어질 수 있으며 모든 거래의 D+14 지급을 보장하지 않습니다. 지급일 선택은 [정산 배치 결정](0007-settlement-batch-scope-and-schedule.md#d3-비영업일-처리)을 따르며 배송·PG 입금의 영업일 계산은 유지합니다.

## 감수하는 비용과 검증

월 2회보다 송금 건수·운영 빈도가 늘 수 있고 PG 입금 전에는 플랫폼 자금이 묶입니다. 초기 자금·PG 입금·입금 후 환불·지급의 보존과 조회/복구를 모의 환경에서 검증합니다. P/M은 플랫폼 부담이며 PG 미수에 섞지 않습니다. 실제 원가·매출·판매자 만족 개선을 확인한 결과는 아닙니다.

- 시간: 주말·주입 공휴일·발송 지연·배송 작업 지연, 환불 마감 직전/정각/직후, 배치 정각의 확정.
- 예약·복구: 환불/지급 경합, 이벤트 중복·역순·지연, 대상 고정 뒤 중단, 보류 해제와 지급 응답 유실.
- 재원: 시험 전 전체 지급·환불 자금 확보, PG 입금 전 지급, 동시 지급·입금/환불 경쟁, 중복 입금과 최종 잔액 대조.

[개발 리뷰 범위](../../CONTRIBUTING.md#개발-리뷰-범위)에 따라 고정 입력·Clock으로 검사합니다. 사업 수치 최적화·실은행 계약·실자금 조달·지급 후 환불/법적 회수·판매자 구독은 이번 확정 범위 밖입니다. 문서·OpenAPI 검사가 금융 동작 검증을 대신하지 않습니다.
