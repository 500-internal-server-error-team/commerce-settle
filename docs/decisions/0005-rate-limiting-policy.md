# 로그인·비밀번호 복구 요청 제한 정책

## 1. 목적
반복적인 로그인 시도 및 비밀번호 복구 요청을 제한하여 계정 공격, 자동화 요청, 불필요한 이메일·문자 발송을 방지한다.

## 2. 구현 방식
- Redis 기반 Rate Limiting을 적용한다.
- 여러 Spring Boot 인스턴스에서 동일한 제한 기준을 공유한다.
- Redis 카운터 증가와 만료 시간 설정은 원자적으로 처리한다.
- 제한 초과 시 HTTP 429 응답과 재시도 가능 시간을 제공한다.

## 3. 초기 정책 제안
- 로그인: 계정별 5분 동안 실패 5회
- 로그인: IP별 1분 동안 요청 30회
- 비밀번호 복구: 계정별 10분 동안 요청 3회
- 비밀번호 복구: IP별 10분 동안 요청 10회

위 수치는 초기 제안이며 부하 테스트와 보안 검토 후 확정한다.

## 4. 보안 고려사항
- 로그인 성공 요청은 실패 횟수에 포함하지 않는다.
- 계정 기준 제한과 IP 기준 제한을 함께 적용한다.
- 계정 존재 여부가 외부 응답에 노출되지 않도록 한다.
- 비밀번호 복구 요청의 중복 발송을 방지한다.
- Redis 장애 시 인증 요청의 처리 정책을 정의한다.
- 제한 정책과 설정값은 환경 설정으로 관리한다.

## 5. 테스트
- 허용 횟수 경계값 테스트
- 제한 시간 만료 테스트
- 다중 서버 요청 테스트
- 동시 요청 테스트
- Redis 장애 테스트
- 비밀번호 복구 중복 요청 테스트

## 6. 향후 개선
트래픽 및 공격 패턴을 분석하여 Fixed Window에서 Sliding Window 또는 Token Bucket 방식으로 확장할 수 있다.

### 초기 요청 제한 수치 선정 근거

초기 제한 수치는 인증 보안, 외부 메시지 발송 비용, 정상 사용자 편의성을 함께 고려하여 설정한다. 해당 값은 절대적인 보안 표준이 아닌 초기 운영 정책이며, 부하 테스트와 보안 검증 결과에 따라 조정한다.

- **로그인 계정별 5분 동안 실패 5회:** 비밀번호 추측 공격을 억제하면서 일시적인 비밀번호 오입력을 허용하기 위한 기준이다.
- **로그인 IP별 1분 동안 요청 30회:** 특정 IP에서 발생하는 단시간 대량 로그인 요청을 제한하기 위한 기준이다.
- **비밀번호 복구 계정별 10분 동안 요청 3회:** 동일 계정에 대한 반복 복구 요청과 이메일·문자 발송 남용을 줄이기 위한 기준이다.
- **비밀번호 복구 IP별 10분 동안 요청 10회:** 여러 계정을 대상으로 반복되는 복구 요청을 제한하고 외부 메시지 발송 남용을 방지하기 위한 기준이다.

계정별 제한은 특정 계정에 대한 반복 공격을 방어하고, IP별 제한은 다수 계정을 대상으로 하는 자동화 요청을 억제한다. 두 정책을 병행하여 단일 기준만 적용했을 때 발생할 수 있는 우회 가능성을 줄인다.

향후 정상 사용자 요청량, 제한 발생률, 오탐률, Redis 처리 지연 및 동시 요청 테스트 결과를 바탕으로 제한 횟수와 시간 창을 조정한다. IP 공유 환경에서 발생할 수 있는 정상 사용자 차단과 공격자가 의도적으로 계정을 제한시키는 계정 잠금 공격도 함께 고려한다.
