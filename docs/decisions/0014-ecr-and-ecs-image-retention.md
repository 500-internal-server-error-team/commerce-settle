# ECR과 EC2의 컨테이너 이미지 보관 정책

- 제안일: 2026-11-11
- 상태: 제안·팀 검토 중. 정책 적용과 AWS 동작은 미검증
- 범위: ECR 저장소의 수명 주기 정책, ECS 컨테이너 인스턴스(EC2)의 이미지 정리 설정, 디스크 감시

## 배경

`v*` 태그를 push하면 [publish 잡](../../.github/workflows/ci.yml)이 모듈별 `linux/arm64` 이미지를 ECR에 push합니다. 이미지 태그는 `모듈-태그명`(예: `gateway-v1.2.0`)이므로, 같은 태그를 다시 push하면 이전 이미지는 태그가 떨어진 untagged 상태로 남습니다. 정리하지 않으면 ECR 저장소와 각 EC2의 EBS 디스크에 이미지가 계속 쌓입니다. 저장소에는 현재 정리 정책이 없으며, CI도 삭제 작업을 하지 않습니다.

EC2는 ECS 에이전트가 pull한 이미지를 캐시합니다. 에이전트는 사용하지 않는 이미지를 주기적으로 지우지만, 디스크 사용량을 기준으로 지우지는 않는 것으로 보입니다. 이 점은 공식 문서로 재확인이 필요합니다.

## 결정

### 1. ECR 수명 주기 정책

ECR은 정책을 하루 단위로 평가합니다. 정책 규칙은 다음과 같습니다.

| 규칙 | 대상 | 조건 | 동작 |
| --- | --- | --- | --- |
| 1 | untagged 이미지 | 푸시 후 1일 경과 | 만료 |
| 2~6 | 모듈별 `v*` 태그 이미지 (`gateway-v`, `commerce-v`, `payment-v`, `settlement-v`, `finance-mock-v`) | 같은 접두사 이미지가 10개 초과 | 오래된 것부터 만료 |

- 규칙 2~6은 모듈마다 접두사를 하나씩 둔 별도 규칙입니다. ECR은 한 규칙에 여러 `tagPrefixList` 접두사를 넣으면 **모든** 접두사를 가진 이미지만 선택하므로, 여러 모듈을 한 규칙에 묶으면 아무 이미지도 선택되지 않습니다.
- 1일은 재배포로 생긴 untagged 이미지를 다음 날 정리하겠다는 뜻입니다. untagged 이미지는 롤백 대상으로 보지 않습니다.
- 태그 이미지 10개는 롤백 대상을 여러 버전 남기기 위한 값입니다. 롤백은 이 범위 안의 `v*` 태그 버전으로만 합니다.

#### 보존의 한계와 대응

ECR 규칙은 실행 중이거나 롤백용인 digest를 **직접 보호할 수 없습니다**. 보존 조건을 표현하는 기능이 없고, 태그로 제외하는 방식도 없습니다. 따라서 다음 조건을 함께 지킵니다.

- **배포 원칙:** 운영 중인 버전이 최근 10개 `v*` 태그 밖으로 밀리기 전에 재배포하거나 보존 개수를 올립니다. 이 조건이 깨지면 해당 digest는 만료되어 캐시가 없는 EC2에서 Task 복구가 실패할 수 있습니다.
- **배포 전 확인:** 배포 시 `aws ecs describe-tasks`로 실행 중인 이미지 digest를 확인하고, 정책 미리보기(`start-lifecycle-policy-preview`) 결과에 그 digest가 포함되지 않는지 대조합니다. 포함되면 적용하지 않습니다.
- **호스트 캐시:** ECS 에이전트는 실행 중인 이미지를 지우지 않으므로, 이미 떠 있는 Task는 ECR 만료의 영향을 받지 않습니다. 영향은 새 EC2로 이동하거나 Task를 다시 pull해야 할 때 나타납니다.

### 2. EC2(ECS 컨테이너 인스턴스) 이미지 정리

에이전트의 기본 정리 기능을 유지하고, 값을 user data의 `/etc/ecs/ecs.config`에 명시합니다.

```bash
ECS_IMAGE_CLEANUP_INTERVAL=10m
ECS_IMAGE_MINIMUM_CLEANUP_AGE=1h
ECS_NUM_IMAGES_DELETE_PER_CYCLE=10
```

- `ECS_IMAGE_CLEANUP_INTERVAL`: 기본값 30분을 10분으로 줄입니다.
- `ECS_IMAGE_MINIMUM_CLEANUP_AGE`: 기본값 1시간을 유지합니다. pull 직후 이미지가 지워지지 않게 합니다.
- `ECS_NUM_IMAGES_DELETE_PER_CYCLE`: 기본값 5를 10으로 올립니다. 배포가 잦을 때 누적 속도를 따라가기 위한 값입니다.

에이전트 정리는 실행 중인 컨테이너가 쓰는 이미지를 지우지 않습니다. 에이전트 버전은 1.13.0 이상이어야 합니다.

### 3. 디스크 감시

CloudWatch 에이전트로 EC2의 디스크 사용률을 수집하고 80% 이상이면 알람을 보냅니다. 임계치는 EBS 용량에 맞춰 조정합니다.

## 검토한 대안

| 안 | 내용 | 채택하지 않은 이유 |
| --- | --- | --- |
| 콘솔에서만 정책 설정 | 수명 주기 정책을 콘솔에 직접 입력 | 설정이 코드 밖에 있어 리뷰와 재현이 불가능 |
| CI에 정리 잡 추가 | 태그 push 때 오래된 이미지 삭제 | CI 역할에 삭제 권한이 필요하고, 실패하면 배포 파이프라인이 막힘 |
| `docker image prune` 주기 실행 | systemd timer로 미사용 이미지 삭제 | 에이전트 정리와 동작이 겹쳐 원인 추적이 어려움 |
| 정리 끄기 | 이미지 누적 허용 | 2대 EC2의 EBS 용량이 제한되어 있어 부적합 |

## 결과와 한계

- ECR 정책 값과 에이전트 설정 값은 제안입니다. 적용 전에 `aws ecr get-lifecycle-policy`로 기존 정책이 있는지 확인합니다.
- 에이전트 정리가 디스크 임계치와 무관하게 주기·개수 기준으로만 동작한다면, 디스크 알람이 유일한 임계치 감시가 됩니다. 알람이 울렸을 때 수동으로 정리할 절차가 필요합니다.
- 1일 untagged 만료는 같은 태그를 짧은 간격으로 다시 push하는 흐름에서 이전 이미지를 바로 잃게 합니다. 롤백 대상은 태그가 있는 이미지여야 합니다.
- 이 ADR은 정책 방향만 정합니다. 정책 JSON과 user data 변경은 별도 구현 PR에서 다룹니다.

## 검증 계획

1. 정책 JSON을 `aws ecr start-lifecycle-policy-preview`로 미리보기 실행해 규칙별 만료 대상을 확인한 뒤, `aws ecr put-lifecycle-policy`로 적용합니다.
2. 테스트 EC2에서 `ecs.config` 값이 적용됐는지 `/etc/ecs/ecs.config`와 에이전트 로그로 확인합니다.
3. 디스크 알람을 임계치 낮춤으로 한 번 발생시켜 알림이 도달하는지 확인합니다.
