# ECR과 EC2의 컨테이너 이미지 보관 정책

- 제안일: 2026-11-11
- 상태: ECR은 배포 성공 이미지 1개 보관으로 변경. EC2 정리 설정·디스크 감시는 제안이며 실제 AWS 적용은 별도
- 범위: ECR 저장소의 수명 주기 정책, ECS 컨테이너 인스턴스(EC2)의 이미지 정리 설정, 디스크 감시

## 배경

`v*` 태그를 push하면 [publish 잡](../../.github/workflows/ci.yml)이 모듈별 `linux/arm64` 이미지를 ECR에 push합니다. 이미지 태그는 `모듈-태그명`(예: `gateway-v1.2.0`)이므로, 같은 태그를 다시 push하면 이전 이미지는 태그가 떨어진 untagged 상태로 남습니다. 정리하지 않으면 ECR 저장소와 각 EC2의 EBS 디스크에 이미지가 계속 쌓입니다. 저장소에는 현재 정리 정책이 없으며, CI도 삭제 작업을 하지 않습니다.

EC2는 ECS 에이전트가 pull한 이미지를 캐시합니다. [자동 정리](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/automated_image_cleanup.html)는 컨테이너 참조 여부·이미지 나이·주기·개수를 기준으로 하므로 디스크 사용률은 별도로 감시합니다.

## 결정

### 1. 배포 성공 이미지 보관

업로드 순서로 최근 10개를 보관하던 제안을 대체합니다. 새 이미지 게시가 성공해도 실제 배포는 실패할 수 있어, 개수 기반 ECR 수명 주기 정책만으로 실행·복구 이미지를 보호할 수 없습니다.

앱 배포 도구가 전체 서비스의 배포·HTTPS 검증 후 실제 실행 digest를 확인하고, 모듈별 배포 성공 이미지 1개와 필수 manifest만 보관합니다. 배포·롤백 중에는 기존 이미지를 유지합니다. 정리 실패는 정상 배포와 분리하고 정리만 재시도합니다. 세부 조건·권한·전환·실패 복구는 [ECR 이미지 자동 정리](../development.md#ecr-이미지-자동-정리)가 기준입니다.

이 방식은 보관량을 줄이는 대신 성공 배포 이후 이전 이미지로 즉시 롤백하는 기능을 제공하지 않습니다. 소스는 Git에 보존하며 복구에는 새 릴리스 빌드가 필요합니다.

### 2. EC2(ECS 컨테이너 인스턴스) 이미지 정리

에이전트의 기본 정리 기능을 유지하고, 값을 user data의 `/etc/ecs/ecs.config`에 명시합니다.

```bash
ECS_IMAGE_CLEANUP_INTERVAL=10m
ECS_IMAGE_MINIMUM_CLEANUP_AGE=1h
ECS_NUM_IMAGES_DELETE_PER_CYCLE=10
```

- `ECS_IMAGE_CLEANUP_INTERVAL`: 기본값 30분을 10분으로 줄입니다.
- `ECS_IMAGE_MINIMUM_CLEANUP_AGE`: 기본값 1시간을 유지합니다. pull 직후 이미지가 지워지지 않게 합니다.
- `ECS_NUM_IMAGES_DELETE_PER_CYCLE`: 기본값 5를 10으로 올립니다. 배포가 잦을 때 누적 속도를 따라가기 위한 값입니다.

에이전트 정리는 실행 중인 컨테이너가 쓰는 이미지를 지우지 않습니다. 에이전트 버전은 1.13.0 이상이어야 합니다.

### 3. 디스크 감시

CloudWatch 에이전트로 EC2의 디스크 사용률을 수집하고 80% 이상이면 알람을 보냅니다. 임계치는 EBS 용량에 맞춰 조정합니다.

## 검토한 대안

- **최근 업로드 1개를 ECR 정책으로 보관:** 배포 실패에도 실행 이미지가 삭제될 수 있어 사용하지 않습니다.
- **최근 10개와 current·rollback·candidate 보호 태그:** 복구 여지는 넓지만 최신 성공 이미지 1개만 보관하려는 목표와 달라 대체합니다.
- **배포 성공 후 정리:** 실행 상태를 확인할 수 있고 같은 배포 도구에서 실패·재시도를 관리할 수 있어 선택합니다. CI 역할에 저장소 한정 삭제 권한이 필요하며 게시·배포·수동 작업의 직렬화가 전제입니다.
- EC2의 `docker image prune` 예약은 ECS 에이전트 정리와 겹치므로 추가하지 않습니다. ECR 원본과 호스트 캐시는 별도입니다.

## 결과와 한계

ECR 정리의 실제 적용·검증은 AWS 권한·기존 정책 확인 후 별도로 수행합니다. 앱 배포가 꺼진 환경의 이미지 게시만으로는 정리가 실행되지 않습니다. EC2 정리 값·알람 역시 이 결정 기록만으로 적용되지 않습니다. 에이전트 정리는 디스크 사용률을 보장하지 않으므로 용량 감시를 유지합니다.
