# ECR과 EC2의 컨테이너 이미지 보관 정책

- 제안일: 2026-11-11
- 상태: 제안·팀 검토 중. 정책 적용과 실제 AWS 검증은 미실행
- 범위: ECR 저장소의 수명 주기 정책, ECS 컨테이너 인스턴스(EC2)의 이미지 정리 설정, 디스크 감시

## 배경

`v*` 태그를 push하면 [publish 잡](../../.github/workflows/ci.yml)이 모듈별 `linux/arm64` 이미지를 ECR에 push합니다. 이미지 태그는 `모듈-태그명`(예: `gateway-v1.2.0`)이므로, 같은 태그를 다시 push하면 이전 이미지는 태그가 떨어진 untagged 상태로 남습니다. 정리하지 않으면 ECR 저장소와 각 EC2의 EBS 디스크에 이미지가 계속 쌓입니다. 저장소에는 현재 정리 정책이 없으며, CI도 삭제 작업을 하지 않습니다.

EC2는 ECS 에이전트가 pull한 이미지를 캐시합니다. [자동 정리](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/automated_image_cleanup.html)는 컨테이너 참조 여부·이미지 나이·주기·개수를 기준으로 하므로 디스크 사용률은 별도로 감시합니다.

## 결정

### 1. ECR 수명 주기 정책

ECR은 [만료 조건을 충족한 이미지를 24시간 이내에 삭제](https://docs.aws.amazon.com/AmazonECR/latest/userguide/LifecyclePolicies.html)합니다. 작은 규칙 번호가 높은 우선순위이며, 아래 모듈은 `gateway`, `commerce`, `payment`, `settlement`, `finance-mock`입니다.

| 규칙 | 대상 | 조건 | 동작 |
| --- | --- | --- | --- |
| 1 | untagged 이미지 | 푸시 후 1일 경과 | 만료 |
| 2~6 | 모듈별 보호 태그 이미지 (`keep-<모듈>-` 접두사) | 같은 접두사 이미지가 3개 초과 | 오래된 것부터 만료 |
| 7~11 | 모듈별 릴리스 이미지 (`<모듈>-v` 접두사) | 같은 접두사 이미지가 10개 초과 | 보호 대상 외 오래된 것부터 만료 |

- 모듈마다 접두사를 하나씩 둔 별도 규칙을 사용합니다. ECR은 한 규칙의 여러 `tagPrefixList` 접두사를 **모두** 만족하는 이미지만 선택하므로 여러 모듈을 한 규칙에 묶지 않습니다.
- 1일은 태그가 떨어진 시각이 아닌 ECR에 기록된 이미지 push 시각 기준입니다. 이미 하루가 지난 이미지가 untagged가 되면 바로 만료 대상입니다.
- Git의 `v*` 태그와 ECR의 `<모듈>-v*` 릴리스 태그는 재사용·덮어쓰기·수동 삭제하지 않습니다. 비보호 이미지의 수명 주기 만료는 허용합니다. 재빌드에는 새 버전 태그를 발행하며, 보호 태그만 이동할 수 있습니다.
- 릴리스 이미지는 최근 10개를 기본으로 보관합니다. 보호 대상이 이 범위 밖에 있으면 보관 이미지가 10개를 넘을 수 있습니다.

#### 실행·롤백·배포 후보 보호

ECR은 ECS의 실행·롤백 참조를 자동으로 알지 못합니다. 대신 [상위 태그 규칙이 보존하는 이미지는 하위 규칙이 만료할 수 없습니다](https://docs.aws.amazon.com/AmazonECR/latest/userguide/lifecycle_policy_examples.html). 배포 주체가 모듈별 `keep-<모듈>-current`, `keep-<모듈>-rollback`, `keep-<모듈>-candidate` 세 고정 태그를 관리합니다. 각 태그는 digest 하나를 가리키므로 규칙 2~6의 대상은 모듈당 최대 3개입니다. 다른 보호 태그는 만들지 않습니다.

1. 정책 적용 전에 `aws ecs describe-tasks`와 서비스의 Task Definition을 대조해 모든 실행·필수 롤백 digest가 ECR에 존재하고 보호 태그로 덮이는지 확인합니다. 기존 untagged 실행 이미지에도 먼저 보호 태그를 붙입니다. 필요한 digest가 모듈당 3개를 넘거나 누락되면 정책을 적용하지 않습니다.
2. 보호 태그 갱신과 배포는 같은 환경·저장소에서 하나씩 직렬화합니다. 새 후보를 pull하기 전에 `candidate`로 보호합니다. 다음 후보로 태그를 옮기기 전에는 이전 후보 Task가 모두 종료됐고 현재 실행·롤백 대상이 계속 보호되는지 확인합니다.
3. 모든 관련 서비스가 안정화된 뒤 기존 `current`를 `rollback`에 먼저 보존하고 새 digest로 `current`를 옮깁니다. 두 대상의 보호를 확인한 뒤 `candidate`를 제거합니다. 실패하면 기존 `current`·`rollback`을 유지하고 복구와 후보 Task 종료가 끝날 때까지 다음 배포를 막습니다.
4. 정책 미리보기의 만료 목록에 보호 digest가 없음을 확인한 뒤 적용합니다. 호스트 캐시는 실행 중 이미지를 유지하지만, ECR의 원본이 삭제되면 캐시 없는 EC2의 Task 복구가 실패하므로 보존 수단으로 의존하지 않습니다.

이 보호 절차와 태그 재사용 거절을 구현·검증하기 전에는 수명 주기 정책을 적용하지 않습니다.

### 2. EC2(ECS 컨테이너 인스턴스) 이미지 정리

에이전트의 기본 정리 기능을 유지하고, 값을 user data의 `/etc/ecs/ecs.config`에 명시합니다.

```bash
ECS_IMAGE_CLEANUP_INTERVAL=10m
ECS_IMAGE_MINIMUM_CLEANUP_AGE=1h
ECS_NUM_IMAGES_DELETE_PER_CYCLE=10
```

- `ECS_IMAGE_CLEANUP_INTERVAL`: 기본값 30분을 10분으로 줄입니다.
- `ECS_IMAGE_MINIMUM_CLEANUP_AGE`: 기본값 1시간을 유지합니다. pull 직후 이미지가 지워지지 않게 합니다.
- `ECS_NUM_IMAGES_DELETE_PER_CYCLE`: 기본값 5를 10으로 올립니다. 배포가 잦을 때 누적 속도를 따라가기 위한 값입니다.

에이전트 정리는 실행 중인 컨테이너가 쓰는 이미지를 지우지 않습니다. 에이전트 버전은 1.13.0 이상이어야 합니다.

### 3. 디스크 감시

CloudWatch 에이전트로 EC2의 디스크 사용률을 수집하고 80% 이상이면 알람을 보냅니다. 임계치는 EBS 용량에 맞춰 조정합니다.

## 검토한 대안

| 안 | 내용 | 채택하지 않은 이유 |
| --- | --- | --- |
| 콘솔에서만 정책 설정 | 수명 주기 정책을 콘솔에 직접 입력 | 설정이 코드 밖에 있어 리뷰와 재현이 불가능 |
| CI에 정리 잡 추가 | 태그 push 때 오래된 이미지 삭제 | CI 역할에 삭제 권한이 필요하고, 실패하면 배포 파이프라인이 막힘 |
| `docker image prune` 주기 실행 | systemd timer로 미사용 이미지 삭제 | 에이전트 정리와 동작이 겹쳐 원인 추적이 어려움 |
| 정리 끄기 | 이미지 누적 허용 | 2대 EC2의 EBS 용량이 제한되어 있어 부적합 |
| 최근 10개만 보관 | 실행 중 버전이 밀리면 재배포 | 이미지 게시만으로 실행·롤백 digest가 사라질 수 있어 보호 태그를 함께 사용 |

## 결과와 한계

- ECR 정책 값과 에이전트 설정 값은 제안입니다. 적용 전에 `aws ecr get-lifecycle-policy`로 기존 정책이 있는지 확인합니다.
- 에이전트 정리는 디스크 사용률을 낮게 유지한다는 보장이 아닙니다. 알람이 울렸을 때 용량과 미사용 이미지를 점검할 절차가 필요합니다.
- 릴리스 태그 불변성과 보호 태그 관리는 별도 조건입니다. 전자는 재push로 실행 이미지가 untagged가 되는 일을 막고, 후자는 실행·롤백·후보가 최근 10개 밖으로 밀려도 보존합니다.
- 이 ADR은 정책 방향만 정합니다. 정책 JSON·보호 태그 관리·태그 재사용 거절·user data 변경은 별도 구현 PR에서 검증합니다. 실제 AWS 적용 완료를 뜻하지 않습니다.

## 검증 계획

1. 테스트 저장소에서 릴리스 11개 이상과 오래된 `current`·`rollback`·`candidate`, 기존 untagged 실행 이미지를 준비합니다. 보호 태그를 붙인 뒤 `aws ecr start-lifecycle-policy-preview`와 `get-lifecycle-policy-preview`로 보호 digest가 제외되고 일반 만료 대상만 선택되는지 확인합니다.
2. 릴리스 태그 재사용이 거절되는지, 연속 배포·실패 복구 중 이전 후보가 종료되기 전에 보호 태그가 이동하지 않는지 확인합니다. 보호 대상 누락·3개 초과·만료 목록 포함 시 적용과 다음 배포가 차단돼야 합니다. 이 검증 후에만 `aws ecr put-lifecycle-policy`로 적용합니다.
3. 테스트 EC2에서 `ecs.config` 값이 적용됐는지 `/etc/ecs/ecs.config`와 에이전트 로그로 확인합니다.
4. 디스크 알람을 임계치 낮춤으로 한 번 발생시켜 알림이 도달하는지 확인합니다.
